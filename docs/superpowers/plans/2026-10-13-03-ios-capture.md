# DengueSense iOS Ward Capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the iOS capture app: a guided face + fingertip capture with on-device provisional quality checks, an encrypted offline outbox, background upload, and the wording rules of a research-only product.

**Architecture:**
- **Core package:** all logic that doesn't touch a camera or UI lives in `ios/DengueCaptureCore`, a Swift package (Foundation, swift-crypto, GRDB) that runs `swift test` on macOS or Linux.
- **App target:** generated by XcodeGen in `ios/App`. It holds the AVFoundation, Vision and SwiftUI code behind protocols, and its tests run under `xcodebuild` on macOS CI.
- **Server:** the app follows `contracts/openapi-v1.json` from plan 02.

**Tech Stack:** Swift 5.10+, iOS 17+, SwiftUI, AVFoundation, Vision, swift-crypto 3.x, GRDB 6.x, XcodeGen, GitHub Actions `macos-15`.

**Spec:** `docs/superpowers/specs/2026-10-13-ios-ward-capture-app-design.md`. Plan 02's Interfaces blocks give the route shapes.

**Depends on:** for Tasks 8, 11 and 12, plan 02 Task 10 (`contracts/openapi-v1.json`). Tasks 1–7 and 9–10 have no dependencies.

**Environment note:** the dev machine is Windows with no Swift toolchain. Every verification step runs on macOS: a Mac, or the CI workflow added in Task 9. An implementer on Windows writes the code and pushes, and CI is the test runner.

## Global Constraints
- iOS deployment target is 17.0. Only two third-party dependencies are allowed: GRDB and swift-crypto. No analytics or crash SDKs (doc 01 ADR-07).
- No `AVCaptureDeviceInput` for audio. `NSMicrophoneUsageDescription` must **not** be in Info.plist. No Location, Contacts or Photos permissions.
- Only the participant code (masked as `••` + its last 3 digits in notifications) and the bed label are ever shown. No name, NRIC, MRN or face thumbnails.
- Every patient-related screen shows the exact banner text: `Research Use Only — not for diagnosis or treatment decisions. Continue standard care and blood tests.`
- Nurse-facing copy must not contain these terms (whole word, case-insensitive): `diagnose, diagnosis, detect dengue, positive, negative, severity, safe, normal, abnormal, risk, result`. There are exactly two allowlisted strings: the banner above, and `Not validated — do not use for care decisions. Use the monitor value.`
- Camera:
  - frame rate 30 fps, locked
  - exposure duration 10 ms or 20 ms only (50 Hz mains)
  - white balance and focus locked after positioning
  - video HDR, Center Stage and stabilisation off
  - no photo output in the session
- Steps, durations and recaptures:
  - Core steps are `neutral_face` (target 40 s, minimum 30 s) and `fingertip_ppg` (target 30 s, minimum 30 s).
  - Optional steps (`ocular_capture`, `dorsal_tongue`) are disabled by default protocol config.
  - Max recaptures per step: 2 (so 3 attempts in total). Pausing discards the partial recording and does not count as a recapture.
- Quality thresholds (device-side, provisional; server is authoritative):
  - no frame gap >0.5 s
  - missing frames <5%
  - measured fps ≥20
  - yaw, pitch and roll within ±15°
  - distance 20–80 cm
  - face width 40–60% of frame width
  - estimated lux ≥200
  - pulse spectral peak within 0.7–3.5 Hz with SNR ≥6 dB
- Experimental pulse values come only from `GET /v1/scans/:id/experimental`. They are shown only when `enabled == true`, as whole bpm, with a grey "EXPERIMENTAL" chip, **below** the nurse-entered monitor value. They never appear in notifications.
- Files:
  - Capture files are written with `.completeUnlessOpen` (Class B). Sealed files are stored with `.completeUntilFirstUserAuthentication` (Class C).
  - All artefact directories have `isExcludedFromBackup = true`.
  - Deletion means destroying the key.

## Review Focus
1. **Phone locks mid-recording.** The step's partial recording is discarded, and the app resumes at the same step on unlock without counting an attempt. Test in Task 1 (`interruption discards partial without consuming attempt`).
2. **Server requests a repeat after the device accepted.** The outbox moves the session to `needsRepeat`, and the nurse sees the step-level reason, not a generic error. Test in Task 7 (`server 422 DS_QG on quality maps to needsRepeat`).
3. **Pre-signed part URL expires mid-upload (403).** The engine requests a new URL for that part and retries once, rather than failing the whole artefact. Test in Task 12.
4. **Clock wrong on the device.** The stored `captured_at` uses the wall clock plus the measured server offset, and the monotonic duration still drives the step timer. Test in Task 7 (`captured_at corrected by server offset`).
5. **Low storage.** With less than 2 GB free, `canStartCapture` is false with reason `.lowStorage`. Test in Task 1.

### Task 3: Pulse-signal plausibility (POS), pass/fail only

**Files:** Create `Sources/DengueCaptureCore/PulsePlausibility.swift`, `Tests/.../PulsePlausibilityTests.swift`

**Interfaces:**
- Produces: `struct RGBSample { r: Double; g: Double; b: Double }`.
- Produces: `enum PulsePlausibility { static func evaluate(trace: [RGBSample], fps: Double, minSNRdB: Double = 6) -> (passed: Bool, reason: ReasonCode?) }`. The reason is `DS_RPPG_001` for low SNR, or `DS_RPPG_002` when the peak lies outside 0.7–3.5 Hz. **No heart-rate value is returned or exposed publicly**, by design (spec §8: the device preview number is never displayed).
- Algorithm (POS, Wang et al. 2017):
  - Use a sliding window of 1.6 s.
  - Normalise each window by its channel means. Compute `S1 = G − B` and `S2 = G + B − 2R`, then `h = S1 + (σS1/σS2)·S2`, and overlap-add.
  - Take a Hann-windowed periodogram. The peak is the maximum in 0.7–3.5 Hz.
  - SNR (dB) = 10·log10(power within ±0.1 Hz of the peak and of its first harmonic ÷ remaining power in 0.7–3.5 Hz).

- [ ] **Step 1:** Write tests using synthetic traces (deterministic seeded noise):
  - `1.2Hz pulse with SNR 10dB passes`
  - `white noise fails DS_RPPG_001`
  - `5Hz sinusoid (flicker alias) fails DS_RPPG_002`
  - `0.5Hz sinusoid fails DS_RPPG_002`
  - `public API exposes no Double bpm`: a compile-time check that `evaluate`'s return type is the tuple above
- [ ] **Step 2:** Run. Expected: FAIL.
- [ ] **Step 3:** Implement with `Accelerate` vDSP when `canImport(Accelerate)`, otherwise a naive DFT.
- [ ] **Step 4:** Run. Expected: PASS.
- [ ] **Step 5:** Commit: `feat(ios-core): POS pulse plausibility gate`.

### Task 6: Chunked artefact sealer with crypto-shredding

**Files:** Create `Sources/DengueCaptureCore/ArtefactSealer.swift`, `Sources/DengueCaptureCore/KeyStore.swift`, `Tests/.../ArtefactSealerTests.swift`

**Interfaces:**
- Produces: `protocol KeyStore { func newKey() throws -> (id: String, key: SymmetricKey); func key(id: String) throws -> SymmetricKey; func destroy(id: String) throws }`, plus `InMemoryKeyStore` for tests. The app supplies a Secure-Enclave-wrapped Keychain implementation in Task 11.
- Produces: `struct ArtefactSealer { init(keys: KeyStore); func seal(input: URL, output: URL) throws -> SealedArtefact; func open(_ s: SealedArtefact, to: URL) throws }` and `struct SealedArtefact: Codable { keyId: String; path: URL; sha256OfPlaintext: String; sizeBytes: Int64 }`.
- File format:
  - magic `DSv1`, then a 1-byte version, then chunks of up to 1 MiB plaintext
  - each chunk is AES-GCM sealed with nonce = 8 random bytes (per file) + a 4-byte big-endian chunk index
  - AAD = chunk index + an isFinal byte
  - so reordering, truncation and tampering all fail to open
- Errors: `SealerError.keyUnavailable`, `.integrity`.
